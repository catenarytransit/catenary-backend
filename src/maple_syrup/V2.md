# Maple Syrup v2 PostgreSQL pilot

Apply the Diesel migration before deploying Maple, Gentian, Aspen, Birch, Ramonda or Spruce. The default
allowlist is in `maple_syrup_v2.toml`. Set `MAPLE_SYRUP_V2_CONFIG` to an
alternate TOML path; an empty feeds array disables new writes. Exact IDs
and trailing-star prefixes are supported. Existing attempts are not backfilled.

Maple derives v2 from the existing reducer and writes both layouts after
legacy metadata/rows, in a transaction. Departure and single-trip readers, including Spruce HTTP/WebSocket and Aspen's import_alpenrose static schedule lookup, use the compatibility views; other readers remain on legacy tables. Legacy IDs, trip records, calendars, frequencies
and metadata remain authoritative. Structural keys preserve all non-timing
fields, including stop ordering and interpolation flags. Each trip-major row
maps a legacy itinerary ID to a dense, group-local timing index. The stop-major
column has the same order. Payloads use little-endian fixed-width primary
offsets or LSB-first GCD frame-of-reference packing; sparse parallel arrays
preserve exact nullable arrival, departure and interpolated offsets.
The primary is arrival, then departure, then interpolated, or zero; a negative
primary uses zero and an exception. Identical non-null arrival/departure
with null interpolation needs no exception. The version is 1.

Gentian reads the compatibility view, which reconstructs existing itinerary
rows from trip-major payloads where available and falls back per itinerary.
No changes to compiled timetable or Edelweiss are made. The SQL decoder is
a transitional compatibility path, not a routing inner-loop optimization.
Existing cleanup cascades through the representative legacy metadata row.
Chateau reassignment uses the legacy metadata join rather than duplicated keys.

This is a dual-write pilot: do not expect net disk savings until all readers
are migrated and legacy rows can be retired. Departure readers use the stop-major compatibility view and trip readers use trip-major. These views expand matching rows in SQL, so do not expect the benchmark's compressed-column network transfer gains yet. No old data is deleted by the up migration. Roll back application
changes before reverting the migration.

Validation: run cargo test --lib maple_syrup::v2; ingest a configured feed and
compare legacy rows to the compatibility view (both EXCEPT ALL directions)
for the same feed and attempt. Compile the same Gentian region before/after
and compare routing results. Benchmark production ingest and Gentian compile
time before broadening the allowlist.

## API reader parity

Compare the full row contract in both directions for each reader view after ingest:

```sql
SELECT * FROM gtfs.itinerary_pattern_departures WHERE onestop_feed_id = 'f-networkrail'
EXCEPT ALL
SELECT onestop_feed_id, attempt_id, itinerary_pattern_id, stop_sequence,
 arrival_time_since_start, departure_time_since_start, interpolated_time_since_start,
 stop_id, chateau, gtfs_stop_sequence, timepoint, stop_headsign_idx, pickup_type, drop_off_type
FROM gtfs.itinerary_pattern WHERE onestop_feed_id = 'f-networkrail';
```

Repeat with operands reversed, and with itinerary_pattern_trip_reader. Both must return zero rows. Test mixed feeds, loop stops, missing times, dwell, realtime cancellations and frequency departures. This rollout retains existing Rust filtering and response assembly; direct binary column retrieval is a future optimization.

## Aspen and Spruce rollout

- Aspen's `import_alpenrose` fetches full itinerary rows through the trip-major reader. The existing compact itinerary cache, realtime matching, trip IDs, stop sequences and service date handling remain unchanged.
- Spruce's nearby HTTP and streaming departure paths fetch matching stop occurrences through the stop-major reader. Its shared departure lookup does likewise; full itinerary terminal lookup uses trip-major. The trip WebSocket already delegates to the shared `fetch_trip_information` reader.
- Verify an allowlisted feed with real trip updates, including loop stops, dwell and missing/interpolated timings. Compare Aspen's compact itinerary rows and realtime match results to legacy data. Exercise Spruce HTTP and WebSocket nearby and single-trip queries on v1-only and mixed v1/v2 chateaux. No live service or database tests were run in the patch authoring environment.
